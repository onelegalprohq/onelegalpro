Both commands read the committed lock files only: `--locked` audits `composer.lock` and `npm audit` reads `package-lock.json`, so **no `composer install` or `npm ci` runs, no `vendor/` or `node_modules/` exists in the job, and no third-party dependency code or package lifecycle script executes**; nothing is remediated (`npm audit fix`, `composer update`, `npm update` are never invoked) and no manifest or lock file is written. `--ignore-unreachable` is deliberately omitted so an unreachable advisory database fails the check instead of passing as though nothing were found; `--abandoned=report` is pinned explicitly so a future Composer default change cannot silently turn an abandoned package into a merge blocker; `--omit=dev` is deliberately omitted because `package.json` declares no production dependencies and omitting dev dependencies would audit nothing.
