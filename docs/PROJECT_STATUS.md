- **PF-048 — UUIDv7.** The **fourth Foundation Library story**, in the approved order, and the first code under `App\Foundation\Domain\Identity`. Created exactly three framework-independent source types: **`UuidV7`** (`final readonly class` implementing `ValueObject` and nothing else, with a **private constructor**, exactly three public methods — `fromString()`, `toString()`, `equals()` — and no constant or public property), **`UuidV7Generator`** (interface, exactly one public method, `generate(): UuidV7`, no constant, property, constructor, trait, or parent interface), and **`SystemUuidV7Generator`** (final, implements `UuidV7Generator`, one constructor parameter `Clock $clock`, no static property and no state between calls). This gives PF-044 `BusinessIdentifier` and every future module identifier **one validated, canonical, time-sortable identifier primitive and one injectable generation contract** instead of each inventing its own format, validation, and time source. **PF-048 is the first Foundation story to depend on earlier ones in code rather than only in documentation** — `ValueObject` (PF-042), `Clock` (PF-047), and the PF-049 exceptions — which is exactly why those three were sequenced ahead of it. **Native PHP standard library only** (`random_bytes()`, `pack()`, `bin2hex()`): `ramsey/uuid 4.9.3` and `symfony/uid v8.1.0` both support UUIDv7 and are both installed, but **only transitively via `laravel/framework`, and a transitive dependency authorizes nothing** — the same rule PF-047 applied when declining PSR-20 and Carbon; their one real advantage, same-millisecond monotonic increment, holds only within a single process and could not be promised platform-wide anyway, and `ramsey/uuid`'s parser is additionally lenient (accepting brace-wrapped, `urn:uuid:`, unhyphenated, nil, wrong-version, and wrong-variant input), so a wrapper would have implemented strict validation regardless. Because generation sits behind `UuidV7Generator`, **adopting a library later is additive, not breaking.** `Illuminate\Support\Str::uuid7()` was prohibited on two independent grounds: `Illuminate\` is on the PF-049 guard's denylist, and it honours the global mutable `Str::$uuidFactory` hook, which would let unrelated framework test state change a Foundation primitive's output. **Generation is deliberately not a static method on the value object** — a static factory would read ambient time and ambient randomness inside a value object, contradicting the PF-047 rule that domain code never reads ambient system time, and making the timestamp bits untestable; the `Clock` is constructor-injected so `generate()` stays parameterless and a future stateful implementation is unconstrained. **No separate randomness abstraction** was introduced: a substitutable randomness source is a security footgun, and every property that matters is provable without controlling the random bytes. **Validation is strict and total** — one canonical pattern enforces exact length, canonical hyphen positions, hexadecimal-only content, the version nibble `7`, and an RFC variant nibble (`8`, `9`, `a`, `b`), rejecting surrounding whitespace, brace-wrapped and `urn:uuid:` forms, the unhyphenated form, the nil and max UUIDs, every other version, and every reserved variant; **hexadecimal is accepted in either case and normalised to lowercase on the creation path**, per RFC 9562 §4, never during comparison. **Time semantics use the term *time-sortable* throughout, in source, tests, and documentation alike, and the stronger ordering wording it replaces appears nowhere:** values whose encoded millisecond timestamps differ sort by those timestamps both lexically and bytewise; **values created within the same millisecond have no defined relative order; no monotonicity is promised in any scope; clock rollback is permitted and unguarded** (a value created later may sort before one created earlier, and nothing detects, corrects, or reports it); and **no global, cross-process, or cross-host ordering is promised**. **Timestamp range is explicitly enforced:** RFC 9562 §5.7 defines `unix_ts_ms` as a 48-bit unsigned millisecond count, so `SystemUuidV7Generator` verifies the clock's instant against `0` through `281474976710655` inclusive and throws **`InvariantViolation`** outside it, using **integer arithmetic only** with **no floating-point timestamp arithmetic anywhere, on the accepting and the rejecting path alike** — **the bounds are checked before the multiplication, never after**, because `\DateTimeImmutable` can represent instants whose Unix seconds exceed `intdiv(PHP_INT_MAX, 1000)` and a `seconds * 1000` product would then overflow the integer domain and silently become a float, so whole seconds and the millisecond remainder are read as separate integers and compared before being combined (seconds against `intdiv(281474976710655, 1000)`, and only on that final representable second the remainder against `281474976710655 % 1000`, with negative seconds rejected outright) — and **never truncating, wrapping, clamping, or reinterpreting** an unencodable instant — each of which would return a syntactically valid UUID carrying a silently wrong timestamp; the six timestamp bytes come from `pack('J', …)`, which states big-endian explicitly, so assembly never depends on host byte order. **Uniqueness is probabilistic, not proven** — 74 bits of cryptographically secure randomness per millisecond make a collision negligibly unlikely, not impossible, and **no exactly-once generation or collision-impossibility claim is made**. **Exceptions map onto the existing PF-049 taxonomy with no new exception type**: `InvalidArgument` for caller-supplied text that is not a canonical version 7 UUID, `InvariantViolation` for an unencodable clock instant or for generated data that somehow fails validation (retaining the original as the previous exception), and **`\Random\RandomException` propagates untranslated**, because a CSPRNG failure is a catastrophic environment failure rather than a domain condition and must not be swallowed by a handler catching `FoundationException`. **No exception message contains the rejected input or the offending instant.** `app/Foundation/README.md` gained an `Identity` section recording all of this, and its namespace table now records `Identity` as **partially implemented — the three PF-048 types only, with `BusinessIdentifier` (PF-044) still a reservation that does not exist**;
